# 2026-10-17 — SDK audit of product firmware: verdict `rewrite`

OpenSpec change `fix-alarm-buzzer-pulse-blocking`, tasks 4.1–4.2. Scope: `firmware/src/` and `firmware/apps/clock/src/`. Method: grep of every `NRF_*->` register access, `nrf_gpio_*`, `nrfx_*`, `app_*` call.

| File | Peripheral | Access | Class |
|---|---|---|---|
| `board.c` | GPIO (CS, DC, RST, BUSY, buttons, buzzer EN, DCF PON) | `nrf_gpio_*` HAL | HAL (not a driver; fine) |
| `board.c` | CLOCK (LFCLK start) | `NRF_CLOCK->` registers | direct register (no nrfx need) |
| `board.c` | RTC1 (timebase, overflow) | `NRF_RTC1->` registers, `NVIC_EnableIRQ` | **direct register, nrfx_rtc exists** |
| `board.c` | UART0 (console) | `NRF_UART0->` registers (init, RX poll, TX busy-wait) | **direct register, nrfx_uart/uarte exists** |
| `board.c` | UART | `app_uart_get/put` calls at lines 136, 146 | `app_*` library, mixed with the register path |
| `buzzer.c` | PWM0 (2.7 kHz tone) | `NRF_PWM0->` registers, bounded spin on STOPPED | **direct register, nrfx_pwm exists** |
| `buzzer.c` | GPIO BUZZER_EN | `nrf_gpio_pin_*` | HAL |
| `spi_bus.c` | SPIM0 (EPD, LIS3DH) | `NRF_SPIM0->` registers, busy-wait on EVENTS_END | **direct register, nrfx_spim exists** |
| `spi_bus.c` | GPIO SCK/MOSI/MISO/CS | `nrf_gpio_*` | HAL |
| `epd.c` | GPIO DC/RST/BUSY | `nrf_gpio_*`, BUSY polled with `app_poll()` | HAL, polling |
| `lis3dh.c`, `clock.c`, `alarm.c`, `clock_face.c`, `dcf77_classify.c` | none | no direct hardware access | pure logic / via `spi_bus` |
| `apps/clock/src/main.c` | none | calls `board_*` only; `app_poll()` is the project main-loop hook | pure logic |

Software bit-banging: none. All transfers use hardware peripherals.

**Verdict: `rewrite`.** Rule from design decision 3: a peripheral that has an nrfx driver (SPIM, PWM, RTC, UARTE) is driven by registers in product code. This holds for four peripherals: RTC1, UART0, PWM0, SPIM0. No `nrfx_*` call exists anywhere. Direct `NRF_CLOCK` use alone would not trigger it.

Side finding: the console mixes `app_uart_*` calls with direct `NRF_UART0` register init, which is two paths to one peripheral.

Next change: `rewrite-firmware-on-nrf5-sdk-drivers`.
